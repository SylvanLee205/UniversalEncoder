## 1. 根目录应该长什么样

```
Video_ Optimize\
├─ UniversalEncoder_vNN.py            ← 只留一个：当前在用的版本（现为 v87）
├─ Renamer_iPhone_Screenrecording.py  ← 重命名工具（常用，留根目录）
├─ _env_cache.json                    ← 程序自动生成，可删（下次运行重探）
└─ 归档\                               ← 本目录
```

如果根目录出现第二个 `UniversalEncoder_*.py`，说明该归档了 —— 见下面第 3 节。

> 注：根目录还有一个 `1_test\`（4.6 GB 真实视频素材 + 两批压缩产物，2026-10-26 的测试目录），
> 属于**用户真实素材**，未动。要不要收进 `测试素材\` 由用户决定，详见交接文档 §17。

## 3. 版本迭代约定

1. 新版本另存为 `UniversalEncoder_vNN.py`，**放根目录**；
2. **旧版立刻移进 `旧版本\`** —— 根目录永远只留一个程序文件，避免双击错版本；
3. 每 20~30 版挑一个稳定点复制到 `里程碑版本\`，文件名带上日期；
4. 测试脚本跟着版本走，命名 `_selftest_vNN.py` / `_e2e_vNN.py`，放 `测试脚本\`。

### 为什么测试脚本放在归档里还能跑

三个版本的脚本都改成**从自身目录向上逐级查找** `UniversalEncoder_vNN.py`
（最多三级，且会额外查 `归档\旧版本\`），所以放在 `测试脚本\` 里也能直接运行：

```bat
C:\Python311\python.exe "C:\Users\Administrator\Desktop\Video_ Optimize\归档\测试脚本\_selftest_v87.py"
C:\Python311\python.exe "C:\Users\Administrator\Desktop\Video_ Optimize\归档\测试脚本\_e2e_v87.py"
```

> 跑 `_e2e_vNN.py` 时，被测程序靠 PATH 找 ffmpeg。若 shell 的 PATH 不含
> `C:\User Program Files\FFmpeg\bin`，脚本会**显式给子进程补上该目录**，不用手动配环境。

## 4. 怎么还原（全部可逆）

所有归档都是**同一磁盘上的移动**，把文件/文件夹移回 `Video_ Optimize\` 即可，无需重装或重新生成：

| 想恢复 | 从哪移回 |
|---|---|
| 回滚到 v86 | `旧版本\UniversalEncoder_v86.py` → 根目录 |
| 回滚到 v85 / v84 | `旧版本\` 里对应文件 |
| 看技术细节 | `文档\总结\编码参数与问题总结.md`（32 章） |
| 看历史测试数据 | `测试素材\` 整个文件夹 |
| 重跑测试 | `测试脚本\` 里对应版本的两个脚本（可在原地直接跑） |
| 找旧运行日志 | `日志与缓存\_encode_run_20261019.log`（10/19 批次）、`_encode_run.log`（10/17 批次） |

## 5. 两个容易踩的点

1. **`dovi_tool.exe` 已不在项目目录**，它现在在 `C:\User Program Files\DoviTool\`（系统 PATH 里）。
   程序里 `find_dovi_tool()` 会先找脚本同级、再走 PATH，所以位置变了也不影响杜比视界保留功能。
   换机器时把 `dovi_tool.exe` 丢进任意 PATH 目录（或放回程序同级）即可。
2. **`_env_cache.json` / `_workers.json` / `_platform_cache.json` 会自动出现在程序同级目录**，
   这是设计如此（缓存环境探测结果与实测并发数），不是垃圾文件，删掉只是下次重新探测。
   而 `__pycache__\`、`.DS_Store`、`_tmp_vNN\`（测试临时产物）才是可再生的垃圾，可随时清。
