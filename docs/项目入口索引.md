## 这是什么

用 ffmpeg 驱动的**单文件 Python 批量视频压缩工具**（Intel QSV / NVIDIA NVENC 硬编），
6,292 行、中文交互菜单。目标：**同等画质文件最小、同等体积画质最好**，
同时尽量保住原片元数据、竖屏旋转、VFR 与可播性。
iPhone 录屏实测平均省 **86.8%** 体积。当前版本 **v88**（修复 N 卡机器误报 QSV 可用；v87 是纯清理版，功能与 v86 逐字节等价）。

## ③ 检索时的排除清单（**最容易踩的坑，务必看**）

1. **只以根目录的 `UniversalEncoder_v88.py` 为当前实现。**
   本机**已不再保留任何旧版本程序**（2026-11-03 清理，理由：旧逻辑会误导人、且都能从 GitHub 找回）。
   但 **GitHub 仓库里有**：`archive/` 目录是 9 份历史里程碑，`git log` 里还有每一个版本的代码。
   检索 `GOP_AUTO` / `ICQ_CAP_TOLERANCE` / `check_promises` / `build_ffmpeg_command` 时若命中了它们，
   那是**旧逻辑**（例如 v85 的自检基准写死 0.8~2.6 秒、v83 之前上限会被静默跳过），**别当现状用**。

2. **两个视频目录没有可检索的文本，别去 glob 它们**：
   `归档\测试素材\`（8.8 GB，224 个文件，无可检索文本，别去 glob）。
   **交付给别人或拷到别的机器时，这 8.8 GB 也不必带走**（对理解代码零帮助）。
   全量 glob 会很慢，而且极易让 AI 误以为"这些视频是待处理素材"而去动它们。
   **交付给别人或拷到别的机器时，这两个目录不必带走**（占 13.4 GB，对理解代码零帮助）。

3. **项目总结.md 第一~三章是 v37 定稿期的历史记录**（Q32 / 音频 64k / GOP 8 秒）。
   该文件开头的版本提示已经标明；**现行默认值看「六之二 菜单速查（v88）」**。

## ⑤ 三条铁律（都是踩坑换来的，别绕过）

1. **改前先读真实代码**；写盘后**三校验**：`py_compile` + 关键函数存在性 + 字节数未异常缩短。
2. **只有端到端实跑才算验证**。实测数据必须落盘成文件，不接受只在对话里说"应该没问题"。
3. **不得静默绕过用户显式选项**——任何"保护性"逻辑都不许偷偷改掉用户选的值。
   （v83 就是靠这条修好"用户设的码率上限被静默跳过"的 bug。）

补充一条 v86 之后新增的约束：**自检的每条判据都必须来自用户本次的实际选择**，
不许出现独立于用户选项的写死基准（v85 就因为基准写死，导致手动选了 GOP 却被判违规）。

## ⑧ 已知会踩的坑（别重复踩）

| 现象 | 原因与对策 |
|---|---|
| 报「找不到 ffmpeg」 | 当前 shell 的 PATH 不含 `C:\User Program Files\FFmpeg\bin`。给子进程 PATH 加上即可；`_e2e_v88.py` 已内置。**别改程序去迁就环境** |
| `git push` 报 `Connection closed by 198.18.0.x` | **环境侧出口受限，不是认证坏**。等几分钟重试，或换 `ssh.github.com:443`。诊断表见交接文档 §17.3b |
| 远端文件"哈希不一致" | 仓库 `core.autocrlf=true`（存 LF、检出 CRLF），归一化换行后再比，否则会误判"没推上去"（交接文档 §15.1） |
| 喂 stdin 跑 e2e 时菜单序号对不上 | 【1.硬件平台】自动检测成功时**不占用输入行**，序号整体前移一位。先跑探针看它问了哪几步，别猜 |
| 面板版本号与代码不同步 | 改版本后要同步 `APP_VERSION`（v86 漏过一次） |

## ⑨ 目录约定（用户 2026-10-18 亲自定的）

- **根目录永远只留一个 `UniversalEncoder_vNN.py`** —— 理由是"避免双击错版本"。
  每出一版，旧版**不留在本机**（旧逻辑会误导人）；**GitHub 的 git 历史就是回滚点**：
  ```bat
  cd /d "C:\Users\Administrator\Desktop\Video_ Optimize\UniversalEncoder-repo"
  git checkout 1dad901 -- UniversalEncoder.py   :: 取回 v87 的代码
  git checkout 528dd3d -- UniversalEncoder.py   :: 取回 v86 的代码
  git checkout c32662b -- UniversalEncoder.py   :: 取回 v85 的代码
  ```
  （`1dad901`=v87、`528dd3d`=v86、`c32662b`=v85、`c862ece`=v86 提交点；更早的版本用 `git log -- UniversalEncoder.py` 找。）
- `Renamer_iPhone_Screenrecording.py` 是用户常用的重命名工具，**留在根目录**。
- `dovi_tool.exe` 放 PATH（`C:\User Program Files\DoviTool\`），**不放项目目录**（用户嫌容易认错）。
- 测试脚本跟版本走，放 `归档\测试脚本\`。
- 文档三件套必须同步：技术长文（章节序号递增）、`CHANGELOG.md`、`项目总结.md` 菜单速查，
