# UniversalEncoder · 视频批量归档压缩工具

面向 **iPhone 录屏 / 高码率视频的长期归档**：在**画质几乎无损**的前提下把体积压到原片的 **10~20%**，
支持 Intel QSV 与 NVIDIA NVENC 双平台，并且**可以保留杜比视界**。

> 实测：16 个真实录屏（2 并发）**平均体积 −86.8%**，无一个变大，全部成功；
> 杜比视界素材 **8.02 MB → 1.27 MB（−84%）**，压完仍是杜比视界。

---

## 一、特性

| 特性 | 说明 |
|---|---|
| **画质导向编码** | HEVC（QSV/NVENC）走 **ICQ / QVBR**：质量档为主，码率上限只做天花板 |
| **上限自动反解** | 超上限的素材自动抬 Q 重压一次（复用 ICQ 的确定性，收敛即可），实测接管件落点均值 = 上限的 98.5% |
| **杜比视界保留** | DV 源 → 提取 RPU → 编码 → 注回 RPU → 移植 `dvvC` 配置盒，输出仍是 DV profile 8.4 |
| **全菜单可调** | 质量档（含自定义 Q）、码率上限、音频、GOP、质量地板、并发路数、编码档位 |
| **自适应/实测可选** | 编码档位与并发路数都支持"现场实测自动挑"或"手动选择" |
| **无硬编码路径** | 默认用 PATH 里的 ffmpeg；找不到就在脚本目录找（也支持自己改程序名） |
| **失败可控** | 单文件最多重试 3 次；失败清单 + 每文件运行日志（含视频码率/Q/耗时） |
| **启动快** | ffmpeg 探测合并为 1 次进程 + 结果缓存 + 用编码器列表判平台 → **实测 0.1 秒** |

## 二、环境要求

- **Windows**（用到了 QSV/NVENC 与 `shutil.which` 等）
- **Python 3.9+**（无第三方依赖，纯标准库）
- **ffmpeg / ffprobe**：放 PATH，或与脚本同目录。需包含目标硬件编码器（`hevc_qsv` 或 `hevc_nvenc`）
- **可选**：`dovi_tool.exe`（要保留杜比视界时必需）——放到脚本同目录即可
  下载：<https://github.com/quietvoid/dovi_tool/releases>

## 三、快速开始

```bat
:: 1) 把脚本和视频放在一起（或 cd 到视频目录）
python UniversalEncoder.py
:: 2) 菜单一路回车用默认即可
:: 3) 结果在 output\ ，日志在 _encode_run.log
```

## 四、默认参数与依据

```
编码   hevc_qsv / hevc_nvenc（ICQ / QVBR）
质量   Q32          → 1080p NEG≈84 / 720p NEG≈80
上限   2500 kbps    → 只对 1290p60/2K/4K 生效；接管件实测均值 2.46 Mbps
preset medium(QSV) / p5(NVENC) → medium 与 veryslow 实测几乎同画质，但快 1.44 倍
音频   libopus 64k VBR（实际约 56k）
GOP    8 秒         → 收益拐点，约吃到 90% 的省码率收益
并发   2 路         → 吞吐拐点
解码   QSV 零拷贝硬解 → 失败回退 d3d11va → CPU
```

**关键实测结论**（详见 `docs/编码参数与问题总结.md`）：

- **源码率 ≠ 内容难度**：同为 Q32，静态 UI 只出 0.5~1.5 Mbps，屏内视频/游戏/噪点出 2.5~6 Mbps
- **同 Q 数字在不同编码模式下含义不同**：CQP(`-q:v`) 与 ICQ(`-global_quality:v`) 差别巨大
  （1080p Q32：352 kbps/78.3 vs 621 kbps/85.9）
- **降规格不划算**：录屏里的 UI/弹幕是原生分辨率细节，1080p30 同码率比原生低约 5 分
- **Q 是整数、一格约 7~13% 码率** → 码率只能落在 2.3~2.7 的带里，这是可预测性的物理边界

## 五、杜比视界保留

iPhone 的杜比视界是 **profile 8.4（HLG 基底 + RPU 动态元数据）**。本工具用 6 步把 DV 完整保留：

```
① ffprobe 探测 side_data 含 DOVI
② 源提 ES（dovi_tool 不认 MOV/MP4）→ dovi_tool extract-rpu
③ 10bit HLG 编码（零拷贝 QSV）
④ 编码结果提 ES → dovi_tool inject-rpu
⑤ 重封装 -tag:v hvc1 -strict unofficial
⑥ 移植源里的 dvvC 配置盒到输出 hvcC 之后（按偏移包含判断祖先盒）
```

任一步失败 → 保留 HLG 产物 + 日志写明，**不影响整批**。

**限制**：
- **仅「安全模式（output/）」支持**；原地替换是先换源文件，后处理再跑时源已是 HLG
- 编码过程**不能 trim / 改帧率 / 丢帧**（RPU 与帧一一对应），本工具本就不做这些

## 六、注意事项

- **别用「原地替换」压杜比视界**（见上）
- **4K 等高像素率素材**：2.5 Mbps 意味着 bpp≈0.009（自然影像需 0.02~0.03）→ 会看到块状。
  请把上限调到 **5.0~5.5 Mbps**，并开启【12 质量地板】= **Q36**
- **VMAF 依赖测量方法**：同一文件单段抽帧与全片多窗口可差 4~6 分；NEG 模型比默认低约 2.1 分。
  文档中的绝对值只在同一套方法内可比
- 首次运行会在脚本目录生成缓存：`_env_cache.json`、`_qsv_calibration.json`、`_workers.json`（可随时删）
